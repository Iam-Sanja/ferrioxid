# Internationalisation

[Overview](index.md) · Details: [localization.md](localization.md) · Error codes: [error-codes.md](error-codes.md)

**Milestone:** v0.13. German and English apply to the HTML admin, the standard page texts and the central CLI success messages. English is the technical fallback. The Cargo version remains `0.1.0`.

## Responsible files

- `crates/ferrioxid-admin/src/localization.rs` contains the fixed catalogue. The requested name never becomes a file path.
- `POST /admin/preferences` stores `ferrioxid_locale` as an HttpOnly cookie. The document sets `lang`.
- `crates/ferrioxid-api/src/pages.rs` selects the Tera language of the project pages.
- `crates/ferrioxid-cli/src/text.rs` translates the central CLI lines.

## Data flow

1. Without a cookie, `Accept-Language` applies, then `default_locale`, then `fallback_locale`.
2. The language form sends `de` or `en`. Another value remains with the current language. The next GET page shows the new language.
3. The catalogue in `localization.rs` has a German and an English text for each key.
4. Validation display goes through `ferrioxid_core::message_text`. German is used only for `de`; every other locale uses English. A missing code returns `missing message`. SQL, stack traces and `password_hash` become the generic rejection text.

## Limitations

Other languages require a new catalogue, an entry in `supported_locales` and the server-side allowlist `de`/`en`. Model names, columns and authorization codes remain untranslated. The outputs of `ferrioxid migrate` remain in the previous version so that scripts see stable lines.
