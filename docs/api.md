# ferrioxid-api – HTTP routing and response contracts

[For overview](index.md) · **IST file:** `crates/ferrioxid-api/src/lib.rs`.] Date formats: [date-time-types.md](date-time-types.md)]. Invalid values remain 422 with `validation.date`, `validation.time`, `validation.datetime` or `validation.datetime_offset`.

## Responsibility (IST)

The Crate provides `App` as a builder for registration, development bootstrap and Axum router. It must not attempt to automatically detect database models in the workspace. `ApiError` responds with `problem_json` from `ferrioxid-core`. The codes are in [error-codes.md](error-codes.md)]. `detail` remains the fallback for existing tests.

```rust
let app = ferrioxid::App::new(db.clone()).register::<Product>();
app.bootstrap_schema().await?;  // separat, nur Demo/Entwicklung
let router = app.into_router();
let router = ferrioxid::web::prepare(router, &settings);
```

### Registrierung

- `register<M: ModelRepository>(self)` liest `M::descriptor()`.
- `allow_anonymous == true`: GET `list::<M>`, POST `create::<M>`, and on `/{id}` GET `get_one::<M>`, PATCH `update::<M>` and DELETE `delete_one::<M>`.
- `permissions = "authenticated"` or a resource name: session and law. GET checks `read`, POST `create`, PATCH `update`, DELETE `delete`.
- `object_policy = true` without `register_policy`: 403. With `register_policy`, the individual retrieval checks the rule and responds with 404 if rejected. The list remains 403 for regular users.
- Otherwise: same methods over `denied`, 403 each.
- `with_auth` is attached to `AuthService`. `into_router` mounts `/auth/login`, `/auth/logout`, `/auth/me` and `/auth/change-password`.
- Bootstrap memorizes the table and `columns()`, regardless of the release, and only renders the DDL from the detected database backend.
- `into_router()` is attached to `GET /healthz`. The Axum-State is `AppState` with database and optional authentic service.
- Cookie write accesses require `x-csrf-token`. The token is stable per session, see [csrf.md](csrf.md)]. Anonymous demo routes do not check this token because they do not use the session cookie as permission.
- Ferrioxide errors are `application/problem+json` with `type`, `title`, `status` and `detail`. 422 remains the answer for validation and unknown sorting or filter fields. 409 is reserved and is not generated by the current traders. Axum rejections, for example invalid JSON, retain the Axum format and are not a ferrioxide problem detail. Database texts, hashes, tokens and stack traces do not go to the client.

### HTTP API (IST)

| Route | Code | Response |
|---|---|---|
| `GET /healthz` | 200 |`{"status":"ok"}`; no DB readiness test|
| `GET /api/v1/products` | 200 | `{"data":[...],"limit":100,"truncated":false}` |
| `GET /api/v1/products/{id}` | 200 / 404 |Typed model / Ferrioxide problem JSON with unknown UUID|
| `POST /api/v1/products` | 201 |created JSON model with server-side UUID|
| `PATCH /api/v1/products/{id}` | 200 / 404 / 422 |updated model, missing UUID or validation|
| `DELETE /api/v1/products/{id}` | 204 / 404 / 422 |empty body only at 204; missing UUID as problem JSON; Foreign Key `restrict` as 422|
|unreleased model, all these methods| 403 | Ferrioxid-Problem-JSON |
|Validation error, unique or foreign key breach| 422 |Ferrioxide Problem JSON without SQL Text|
| Datenbankfehler | 500 |generic message; Detail in the `tracing` log|

There is no authentic system, no API versioning engine, no filter and no offset/cursor. The `/api/v1` prefix comes from the path stored in the model. An invalid UUID in the path answers Axum itself, not `ApiError`.

### Fault Contract (IST)

```json
{"type":"about:blank","title":"Validation failed","status":422,"detail":"name must not be blank"}
```

`ApiError` is a **local newtype** about `FerrioxidError`. This is necessary because of Rust’s Orphan Rule: `IntoResponse` is foreign and `FerrioxidError` belongs to another Crate. Do not remove the newtype. `denied` uses the same error form for GET, POST, PATCH and DELETE. HTTP 204 is returned as `StatusCode::NO_CONTENT` without JSON body. **Exception:** Errors in decoding invalid JSONs occur in Axum's `Json` extractor and retain Axum's own rejection response.

### Safety Border (IST)

If `allow_anonymous = true`, the route can be used without authentication. Only for locally bound demo processes. For real applications, no standard public CRUD endpoints without an Auth and Policy layer.

## SOLL: API-Generator

1. Separate response DTOs if read and write view should no longer be the same model.
2. Object/field policies before data access and response serialization.
3. Conflict responses such as HTTP 409 for version conflicts. The current PATCH is Last-Write-Wins in a statement.
4. Cursor-based pagination with stable sequence; Limits hard.
5. Allowlists for sortable and filterable fields.
6. Declare versioning explicitly and do not guess from path names.
7. OpenAPI metadata without duplicate manual schema definitions.
8. JSON error contract with structured validation details and RFC-9457 matching.

## API-Abnahmetests

- POST successful: 201, UUID, data values and Boolean default.
- GET `/{id}`: 200 if the UUID exists, 404 if the UUID does not exist.
- PATCH only `name`: Price and `active` remain. `{}` does not change anything. Empty name and negative price make 422. Unknown UUID is 404.
- DELETE: 204 without body, then GET and re-DELETE make 404.
- Private models: List, GET, PATCH and DELETE provide 403 with `title: Forbidden`.
- POST `name: ""` or blank: 422.
- GET 101+ Elemente: 100 Daten + `truncated: true`.
- Unreleased model: 403 with problem JSON.
- DB error: no secrets in the answer.
- GET `/healthz` is not misunderstood as a DB readiness test.

## Admin

`App::with_admin` attaches `/admin/api` and `/admin` to the same router. The public CRUD API and its limit of 100 remain unchanged. `allow_anonymous` still applies there and does not apply to the admin. Details, errors and tests: [admin-baking.md](admin-backend.md)].
