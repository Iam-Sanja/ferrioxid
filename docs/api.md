# ferrioxid-api – HTTP routing and response contracts

[Overview](index.md) · **Implemented file:** `crates/ferrioxid-api/src/lib.rs`. Date formats: [date-time-types.md](date-time-types.md). Invalid values remain 422 with `validation.date`, `validation.time`, `validation.datetime` or `validation.datetime_offset`.

## Responsibility (Implemented)

The Crate provides `App` as a builder for registration, development bootstrap and Axum router. It must not attempt to automatically detect database models in the workspace. `ApiError` responds with `problem_json` from `ferrioxid-core`. The codes are in [error-codes.md](error-codes.md). `detail` remains the fallback for existing tests.

```rust
let app = ferrioxid::App::new(db.clone()).register::<Product>();
app.bootstrap_schema().await?;  // separat, nur Demo/Entwicklung
let router = app.into_router();
let router = ferrioxid::web::prepare(router, &settings);
```

### Registration

- `register<M: ModelRepository>(self)` reads `M::descriptor()`.
- `allow_anonymous == true`: GET `list::<M>`, POST `create::<M>`, and on `/{id}` GET `get_one::<M>`, PATCH `update::<M>` and DELETE `delete_one::<M>`.
- `permissions = "authenticated"` or a resource name: session authentication and permission checks. GET checks `read`, POST `create`, PATCH `update`, DELETE `delete`.
- `object_policy = true` without `register_policy`: 403. A registered policy supplies query scopes for lists and record access; rejected individual records return 404. The default read scope is `None`, so regular users see no rows unless the policy grants access.
- Otherwise: same methods over `denied`, 403 each.
- `with_auth` binds an `AuthService`. `into_router` mounts `/auth/login`, `/auth/logout`, `/auth/me` and `/auth/change-password`.
- Bootstrap records each table and its `columns()`, regardless of route access, and renders DDL for the detected database backend.
- `into_router()` adds `GET /healthz`. `AppState` contains the database and an optional authentication service.
- Cookie write accesses require `x-csrf-token`. The token is stable per session, see [csrf.md](csrf.md). Anonymous demo routes do not check this token because they do not use the session cookie as permission.
- Ferrioxid errors are `application/problem+json` with `type`, `title`, `status` and `detail`. 422 remains the answer for validation and unknown sorting or filter fields. 409 is reserved and is not generated by the current handlers. Axum rejections, for example invalid JSON, retain the Axum format and are not a Ferrioxid problem detail. Database texts, hashes, tokens and stack traces do not go to the client.

### HTTP API (Implemented)

| Route | Code | Response |
|---|---|---|
| `GET /healthz` | 200 |`{"status":"ok"}`; no DB readiness test|
| `GET /api/v1/products` | 200 | `{"data":[...],"limit":100,"truncated":false}` |
| `GET /api/v1/products/{id}` | 200 / 404 |Typed model / Ferrioxid problem JSON with unknown UUID|
| `POST /api/v1/products` | 201 |created JSON model with server-side UUID|
| `PATCH /api/v1/products/{id}` | 200 / 404 / 422 |updated model, missing UUID or validation|
| `DELETE /api/v1/products/{id}` | 204 / 404 / 422 |empty body only at 204; missing UUID as problem JSON; Foreign Key `restrict` as 422|
| Model without an access policy, all methods | 403 | Ferrioxid problem JSON |
|Validation error, unique or foreign key breach| 422 |Ferrioxid Problem JSON without SQL Text|
| Database error | 500 | Generic response; internal details stay in the `tracing` log. |

Authentication, sessions, role permissions and object policies are implemented through `ferrioxid-auth`. Bind an auth service and the required policies for protected models; see [auth.md](auth.md) and [query-scopes.md](query-scopes.md). Generated public REST lists still use the fixed 100-record limit rather than offset/cursor pagination or the admin list-filter interface. `/api/v1` is simply the path declared by a model, not a versioning engine. Axum itself rejects an invalid UUID path value.

### Error contract (implemented)

```json
{"type":"about:blank","title":"Validation failed","status":422,"detail":"name must not be blank"}
```

`ApiError` is a **local newtype** around `FerrioxidError`: Rust's orphan rule prevents implementing the foreign `IntoResponse` trait directly for a type defined in another crate. `denied` uses the same problem response for GET, POST, PATCH and DELETE. HTTP 204 uses `StatusCode::NO_CONTENT` without a JSON body. The JSON example above is abbreviated; current problem responses also include the stable `code`. Invalid JSON is rejected by Axum's `Json` extractor using its own response.

### Security boundary (implemented)

If `allow_anonymous = true`, a request without a session cookie can be used without authentication. A request that sends the configured session cookie or `ferrioxid_anonymous` still needs a valid CSRF proof on POST, PUT, PATCH and DELETE. Only for locally bound demo processes. For real applications, no standard public CRUD endpoints without an Auth and Policy layer.

## Planned API generator

1. Separate response DTOs if read and write view should no longer be the same model.
2. Object/field policies before data access and response serialization.
3. Conflict responses such as HTTP 409 for version conflicts. The current PATCH is Last-Write-Wins in a statement.
4. Cursor-based pagination with stable ordering and enforced limits.
5. Allowlists for sortable and filterable fields.
6. Declare versioning explicitly and do not guess from path names.
7. OpenAPI metadata without duplicate manual schema definitions.
8. JSON error contract with structured validation details and RFC-9457 matching.

## API acceptance tests

- POST successful: 201, UUID, data values and Boolean default.
- GET `/{id}`: 200 if the UUID exists, 404 if the UUID does not exist.
- PATCH only `name`: Price and `active` remain. `{}` does not change anything. Empty name and negative price make 422. Unknown UUID is 404.
- DELETE: 204 without body, then GET and re-DELETE make 404.
- Private models: List, GET, PATCH and DELETE provide 403 with `title: Forbidden`.
- POST with `name: ""` or whitespace-only input: 422.
- GET with more than 100 records: 100 items and `truncated: true`.
- Unreleased model: 403 with problem JSON.
- DB error: no secrets in the answer.
- GET `/healthz` is not misunderstood as a DB readiness test.

## Admin

`App::with_admin` adds `/admin/api` and `/admin` to the same router. Generated public CRUD lists retain their 100-record limit. `allow_anonymous` controls public model routes and does not grant admin access. See [admin-backend.md](admin-backend.md) for admin responses, errors and tests.
